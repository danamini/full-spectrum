# Full Spectrum: working notes

Start with `docs/plan.md`: section 10 (next work) and 9 (decisions). The README has the file map.

- **Same shape as Molecule Viewer** (`../molecule-viewer`): static site, no build step, ES modules,
  three.js r170 by import map, Playwright smoke test. Borrow its patterns before inventing new ones.
- **One definition:** constants and formulas live in `js/physics.js`, colour science in `js/colour.js`, band
  edges in `js/bands.js` (the visible range included); things are given in the unit they are known by and
  converted, never worked out by hand. `data/*.js` and `assets/sky/` are generated by `tools/`.
- **Accuracy, credited:** every number, dataset and image gets its source when it first appears;
  sources listed in the README's Data section once there is one. Band boundaries are conventions:
  say so rather than drawing hard edges.
- **Real colour vs false colour:** only the visible band is drawn in real (CIE-derived) colour;
  everything else is false colour, and must look it.
- **a sibling app is private.** Links to it stay behind the switch in `js/links.js`, off by default;
  never put its unpublished content or addresses in this repo.
- **Checks:** `node tests/physics.mjs` (seconds) as you go; `npm test` (about five minutes, a headless browser)
  before committing. A fixed bug gets a test. `node tools/shot.mjs <url> <dir> <hash>...` for screenshots;
  look at them before calling a visual change done.
- **Licences:** `data/cie1931.js` is CC BY-SA 4.0 (share-alike); NIST lines are © NIST with the citation they
  ask for. A new image or dataset goes in `docs/credits-*.md` with its licence before it ships.
- Repo: private `danamini/full-spectrum`. Commit as work lands.
